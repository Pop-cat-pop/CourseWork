== Требование к разработке ПО

*   Используемая платформа: отладочная плата https://www.waveshare.com/product/arduino-2/boards-kits/nucleo/xnucleo-f411re.htm[XNucleo-F411RE];
*   Питание должно быть автономным;
*   Программное обеспечение должно выполнять измерение температуры, давления и влажности;
**  Период измерения: 500 мс;
**  Применение цифрового фильтра к измеренным значениям по формуле: 

[latexmath]
++++
\tau = \int\binom{1-e^\frac{-dt}{RC}, RC > 0 sec}{1,RC \leq 0 sec}
++++
[latexmath]
++++
FilteredValue = OldFiltered + (Value - OldValue) * \tau
++++
где \( dt = 500 мс \); +
\(Value \) — текущее нефильтрованное измеренное значение температуры; +
\(OldValue\) — предыдущее фильтрованное значение.

*   Используемые датчики: 
**  https://www.rlocman.ru/i/File/2022/07/25/bst-bme280-ds002.pdf[BME280] 
**  https://cdn.sparkfun.com/datasheets/Sensors/Temp/DS18B20.pdf[DS18B20]
*   Обмен данными с датчиком: интерфейс I2C2;
*   Сохранение данных при отключении питания;
*   Изменение критических значений температуры, давления и влажности по протоколу обмена данных через USART;
*   Вывод данных: через диод с периодом 1 секунды;
*   Показание критических значений: 
**  Зажигание красного светодиода при Температура моторов > 100℃;
**  Зажигание красного светодиода при Температура аккумулятора > 60℃;
*   Архитектура должна быть представлена в виде UML-диаграмм (пакет StarUML);
*   Программная реализация: язык C++, компилятор ARM 8.40.2;
*   При разработке должна использоваться Операционная Система Реального Времени FreeRTOS и https://github.com/lamer0k/RtosWrapper[С++ обертка над ней].

=== Автономное питание
Из-за работы от аккумулятора, энергопотребление критично. Stop Mode — это режим глубокого сна для STM32, где:

*   Потребление снижается до ~10–20 мкА (вместо ~10 мА в рабочем режиме).
*   Процессор останавливается, но сохраняет состояние ОЗУ и регистров.
*   Периферия (таймеры, USART, датчики) отключается, кроме:
**  RTC (для пробуждения по таймеру).
**  GPIO (для внешних прерываний).

**Цикл работы:**

.   Пробуждение каждые 500 мс (по таймеру RTC или таймеру низкой мощности LPTIM).

.   Запуск задач: опрос датчиков → фильтрация → сохранение → индикация.

.   Возврат в Stop Mode.


[source,c++]
.Схема на FreeRTOS:
----
void IdleTask(void *pvParameters) {
  while (1) {
    // Проверка: все задачи завершились
    if (xTaskGetSchedulerState() == taskSCHEDULER_NOT_STARTED) {
      HAL_SuspendTick();  // Остановка системного таймера
      HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
      SystemClock_Config();  // Восстановление тактирования после пробуждения
    }
    vTaskDelay(10);  // Пауза для экономии энергии
  }
}
----

.Полное описание Stop Mode
|===
| **Параметр** | **Описание**

| **Входные условия**
| - Все задачи FreeRTOS приостановлены (`vTaskSuspendAll()`)

| **Сохраняемые данные**

| - По внешнему прерыванию (например, кнопка)

| **Время пробуждения**
| ~5-10 мкс (быстрее, чем после Reset)

| **Энергопотребление**
| *1.8-2.1 мкА* (при 3.3V, без RTC)

| **Ограничения**
| - Нужно переконфигурировать тактирование после пробуждения
|===

=== Измерение параметров

==== Датчик BME280

Модуль BME280 предназначен для измерения атмосферного давления, температуры и влажности. Это очередной датчик давления фирмы Bosch Sensortec для измерения атмосферного давления и температуры. По сравнению с первыми датчиками серии (BMP085 и BMP180) он имеет лучшие характеристики и меньшие размеры. Отличие от датчика BMP280 – наличие гигрометра, что позволяет измерять относительную влажность воздуха и создать на его основе маленькую метеостанцию.

**Технические характеристики:**

-   Напряжение питания: 1.8 ... 5 В
-   Интерфейс: I2C (до 3.4 мГц), SPI (до 10 мГц)
-   Диапазон температуры: -40 ... + 85 °C
-   Влажность: 0 ... 100%
-   Давление: 300 ... 1100 гПа
-   Точность температуры: 0.5 °C
-   Точность влажности: 3% RH
-   Точность давления: 1 hPa

Модуль BME280 нужен в учете мониторинга технического состояния беспилотного летательного аппарата для контролья температуры аккумулятора, измерения высоты через давление и определения влажности окружающей среды.

[cols="1,1,2,1", options="header"]
.Ключевые регистры BME280
|===
| **Адрес** | **Регистр** | **Описание** | **Тип**

| `0xD0`| `ID`| Идентификатор датчика (`0x60` для BME280)| R

| `0xE0`| `RESET`| Сброс датчика (запись `0xB6`)| W

| `0xF2`| `CTRL_HUM`| Настройка измерения влажности| R/W

| `0xF4`| `CTRL_MEAS`| Настройка режима работы и измерений| R/W

| `0xF5`| `CONFIG`| Настройка фильтра и интерфейса| R/W

| `0xFA`| `PRESS_MSB`| Старший байт давления (20-битное значение)| R

| `0xFD`| `TEMP_MSB`| Старший байт температуры (20-битное значение)| R

| `0xFE`| `HUM_MSB`| Старший байт влажности (16-битное значение)| R
|===

Обозначает тип доступа к регистру:

*   R (Read) — регистр только для чтения (например, ID или данные измерений).
*   W (Write) — регистр только для записи (например, RESET).
*   R/W (Read/Write) — регистр для чтения и записи (настройки).


===== Измерение температуры

Литий-ионные/полимерные аккумуляторы опасно перегревать (риск вздутия, возгорания). Для предотвращения вывода из строя аккумуляторов BME280 измеряет температуру с точностью ±1°C и при повышении темпетаруты больше, чем 60°C система:

.   Включает красный светодиод (аварийная индикация);
.   Снижает мощность моторов (через ESC) (не является темой нашей работы и не будет включено в разработку);
.   Пишет лог в память для анализа.

В датчике BME280 используется формула компенсации, которая преобразует сырое значение (adc_T) в температуру в градусах Цельсия. Формула учитывает калибровочные коэффициенты, хранящиеся в памяти датчика.

Датчик возвращает 20-битное значение (3 байта), хранящееся в регистрах 0xFA (MSB), 0xFB (LSB), 0xFC (XLSB):
[source,c++]
.Получение сырого значения (adc_T)
----
uint32_t adc_T = (data[0] << 12) | (data[1] << 4) | (data[2] >> 4);
----

Где data[0..2] — байты, прочитанные из регистров.

Извлекаются из регистров 0x88–0x9F (см. даташит BME280, стр. 23):

[source,c++]
.Калибровочные коэффициенты
----
// Пример чтения коэффициентов (для STM32):
uint16_t dig_T1 = read_u16(0x88);  // Беззнаковое
int16_t  dig_T2 = read_s16(0x8A);  // Знаковое
int16_t  dig_T3 = read_s16(0x8C);  // Знаковое
----

Алгоритм формул компенсаций приведён в даташите (Section 4.2.3).

[source,c++]
.Формула компенсации
----
// Промежуточные переменные
int32_t var1, var2, T;

var1 = ((((adc_T >> 3) - ((int32_t)dig_T1 << 1))) * ((int32_t)dig_T2)) >> 11;
var2 = (((((adc_T >> 4) - ((int32_t)dig_T1)) * ((adc_T >> 4) - ((int32_t)dig_T1))) >> 12) * ((int32_t)dig_T3)) >> 14;

// Финализация
T = var1 + var2;
float temperature = (T * 5 + 128) >> 8;  // В °C, деление на 100
----

где \(dig_T1, dig_T2, dig_T3\) — калибровочные коэффициенты (уникальны для каждого датчика); +
Операции \(>>\) и \(<<\) — битовые сдвиги для оптимизации вычислений (деление/умножение на степени 2); +
Формула устраняет нелинейность датчика.

[source,c++]
.Пример для STM32 чтения температуры
----
float read_bme280_temp() {
    uint8_t data[3];
    HAL_I2C_Mem_Read(&hi2c2, 0x76 << 1, 0xFA, I2C_MEMADD_SIZE_8BIT, data, 3, 100);
    int32_t adc_T = (data[0] << 12) | (data[1] << 4) | (data[2] >> 4);

    // Коэффициенты (заранее прочитаны при инициализации)
    int32_t var1 = (((adc_T >> 3) - (dig_T1 << 1)) * dig_T2) >> 11;
    int32_t var2 = ((((adc_T >> 4) - dig_T1) * ((adc_T >> 4) - dig_T1)) >> 12) * dig_T3) >> 14;
    int32_t t_fine = var1 + var2;

    return (t_fine * 5 + 128) >> 8;  // Температура в °C
}
----

Датчик калибруется на заводе — коэффициенты компенсируют погрешности. Формула обеспечивает точность ±1.0°C в диапазоне -40°C…+85°C. Целочисленные вычисления быстрее операций с плавающей точкой на MCU.

[NOTE]
====
Все калибровочные коэффициенты должны быть прочитаны при инициализации датчика (адреса 0x88…0x9F). Иначе температура будет неверной!
====

*   94 мс при точности 9 бит
*   Интерфейс связи: 1-Wire (OneWire)
*   Корпус: TO-92, SOIC-8 или герметичное исполнение

Интеграция с FreeRTOS BME280
Выделите отдельную задачу для опроса BME280.

Используйте очередь (xQueueSend) для передачи данных фильтрующему модулю.

Для синхронизации используйте семафор (например, при изменении настроек через USART).

Пример потока работы:

sequenceDiagram
    Task BME280->>BME280: Запрос измерения (Forced mode)
    BME280-->>Task BME280: Данные готовы
    Task BME280->>Queue: Отправка сырых данных
    Task Filter->>Queue: Получение данных
    Task Filter->>Task USART: Отправка отфильтрованных значений
