== Требование к разработке ПО

*   Используемая платформа: отладочная плата https://www.waveshare.com/product/arduino-2/boards-kits/nucleo/xnucleo-f411re.htm[XNucleo-F411RE];
*   Питание должно быть автономным;
*   Программное обеспечение должно выполнять измерение температуры, давления и влажности;
**  Период измерения: 500 мс;
**  Применение цифрового фильтра к измеренным значениям по формуле: 

[latexmath]
++++
\tau = \int\binom{1-e^\frac{-dt}{RC}, RC > 0 sec}{1,RC \leq 0 sec}
++++
[latexmath]
++++
FilteredValue = OldFiltered + (Value - OldValue) * \tau
++++
где \( dt = 500 мс \); +
\(Value \) — текущее нефильтрованное измеренное значение температуры; +
\(OldValue\) — предыдущее фильтрованное значение.

*   Используемые датчики: 
**  https://www.rlocman.ru/i/File/2022/07/25/bst-bme280-ds002.pdf[BME280] 
**  https://cdn.sparkfun.com/datasheets/Sensors/Temp/DS18B20.pdf[DS18B20]
*   Обмен данными с датчиком: интерфейс I2C2;
*   Сохранение данных при отключении питания;
*   Изменение критических значений температуры, давления и влажности по протоколу обмена данных через USART;
*   Вывод данных: через диод с периодом 1 секунды;
*   Показание критических значений: 
**  Зажигание красного светодиода при Температура моторов > 100℃;
**  Зажигание красного светодиода при Температура аккумулятора > 60℃;
*   Архитектура должна быть представлена в виде UML-диаграмм (пакет StarUML);
*   Программная реализация: язык C++, компилятор ARM 8.40.2;
*   При разработке должна использоваться Операционная Система Реального Времени FreeRTOS и https://github.com/lamer0k/RtosWrapper[С++ обертка над ней].

=== Автономное питание
Из-за работы от аккумулятора, энергопотребление критично. Stop Mode — это режим глубокого сна для STM32, где:

*   Потребление снижается до ~10–20 мкА (вместо ~10 мА в рабочем режиме).
*   Процессор останавливается, но сохраняет состояние ОЗУ и регистров.
*   Периферия (таймеры, USART, датчики) отключается, кроме:
**  RTC (для пробуждения по таймеру).
**  GPIO (для внешних прерываний).

**Цикл работы:**

.   Пробуждение каждые 500 мс (по таймеру RTC или таймеру низкой мощности LPTIM).

.   Запуск задач: опрос датчиков → фильтрация → сохранение → индикация.

.   Возврат в Stop Mode.


[source,c++]
.Схема на FreeRTOS:
----
void IdleTask(void *pvParameters) {
  while (1) {
    // Проверка: все задачи завершились
    if (xTaskGetSchedulerState() == taskSCHEDULER_NOT_STARTED) {
      HAL_SuspendTick();  // Остановка системного таймера
      HAL_PWR_EnterSTOPMode(PWR_LOWPOWERREGULATOR_ON, PWR_STOPENTRY_WFI);
      SystemClock_Config();  // Восстановление тактирования после пробуждения
    }
    vTaskDelay(10);  // Пауза для экономии энергии
  }
}
----

=== Измерение параметров

==== Датчик BME280

Модуль BME280 предназначен для измерения атмосферного давления, температуры и влажности. Это очередной датчик давления фирмы Bosch Sensortec для измерения атмосферного давления и температуры. По сравнению с первыми датчиками серии (BMP085 и BMP180) он имеет лучшие характеристики и меньшие размеры. Отличие от датчика BMP280 – наличие гигрометра, что позволяет измерять относительную влажность воздуха и создать на его основе маленькую метеостанцию.

**Технические характеристики:**

-   Напряжение питания: 1.8 ... 5 В
-   Интерфейс: I2C (до 3.4 мГц), SPI (до 10 мГц)
-   Диапазон температуры: -40 ... + 85 °C
-   Влажность: 0 ... 100%
-   Давление: 300 ... 1100 гПа
-   Точность температуры: 0.5 °C
-   Точность влажности: 3% RH
-   Точность давления: 1 hPa

Модуль BME280 нужен в учете мониторинга технического состояния беспилотного летательного аппарата для контролья температуры аккумулятора, измерения высоты через давление и определения влажности окружающей среды.

[cols="1,1,2,1", options="header"]
.Ключевые регистры BME280
|===
| **Адрес** | **Регистр** | **Описание** | **Тип**

| `0xD0`| `ID`| Идентификатор датчика (`0x60` для BME280)| R

| `0xE0`| `RESET`| Сброс датчика (запись `0xB6`)| W

| `0xF2`| `CTRL_HUM`| Настройка измерения влажности| R/W

| `0xF4`| `CTRL_MEAS`| Настройка режима работы и измерений| R/W

| `0xF5`| `CONFIG`| Настройка фильтра и интерфейса| R/W

| `0xFA`| `PRESS_MSB`| Старший байт давления (20-битное значение)| R

| `0xFD`| `TEMP_MSB`| Старший байт температуры (20-битное значение)| R

| `0xFE`| `HUM_MSB`| Старший байт влажности (16-битное значение)| R
|===

Обозначает тип доступа к регистру:

*   R (Read) — регистр только для чтения (например, ID или данные измерений).
*   W (Write) — регистр только для записи (например, RESET).
*   R/W (Read/Write) — регистр для чтения и записи (настройки).


==== Измерение температуры

Литий-ионные/полимерные аккумуляторы опасно перегревать (риск вздутия, возгорания). Для предотвращения вывода из строя аккумуляторов BME280 измеряет температуру с точностью ±1°C и при повышении темпетаруты больше, чем 60°C система:

.   Включает красный светодиод (аварийная индикация);
.   Снижает мощность моторов (через ESC) (не является темой нашей работы и не будет включено в разработку);
.   Пишет лог в память для анализа.

[cols="1,3,2", options="header"]
.Регистры BME280 для работы с температурой
|===
| Адрес (HEX) | Назначение | Размер (байт)
| `0x88-0x9F` 
| Калибровочные коэффициенты температуры (T1-T3) 
| 6 (T1:uint16, T2:int16, T3:int16)

| `0xFA` 
| MSB температуры (биты 19-12)
| 1

| `0xFB` 
| LSB температуры (биты 11-4)
| 1

| `0xFC` 
| XLSB температуры (биты 3-0)
| 1 (младшие 4 бита)

| `0xF4` 
| Контрольный регистр (ctrl_meas)
| 1
|===

В датчике BME280 используется формула компенсации, которая преобразует сырое значение (adc_T) в температуру в градусах Цельсия. Формула учитывает калибровочные коэффициенты, хранящиеся в памяти датчика.

Датчик возвращает 20-битное значение (3 байта), хранящееся в регистрах 0xFA (MSB), 0xFB (LSB), 0xFC (XLSB):
[source,c++]
.Получение сырого значения (adc_T)
----
uint32_t adc_T = (data[0] << 12) | (data[1] << 4) | (data[2] >> 4);
----

Где data[0..2] — байты, прочитанные из регистров.

Извлекаются из регистров 0x88–0x9F (см. даташит BME280, стр. 23):

[source,c++]
.Калибровочные коэффициенты
----
// Пример чтения коэффициентов (для STM32):
uint16_t dig_T1 = read_u16(0x88);  // Беззнаковое
int16_t  dig_T2 = read_s16(0x8A);  // Знаковое
int16_t  dig_T3 = read_s16(0x8C);  // Знаковое
----

Алгоритм формул компенсаций приведён в даташите (Section 4.2.3).

[source,c++]
.Формула компенсации
----
// Промежуточные переменные
int32_t var1, var2, T;

var1 = ((((adc_T >> 3) - ((int32_t)dig_T1 << 1))) * ((int32_t)dig_T2)) >> 11;
var2 = (((((adc_T >> 4) - ((int32_t)dig_T1)) * ((adc_T >> 4) - ((int32_t)dig_T1))) >> 12) * ((int32_t)dig_T3)) >> 14;

// Финализация
T = var1 + var2;
float temperature = (T * 5 + 128) >> 8;  // В °C, деление на 100
----

где \(dig_T1, dig_T2, dig_T3\) — калибровочные коэффициенты (уникальны для каждого датчика); +
Операции \(>>\) и \(<<\) — битовые сдвиги для оптимизации вычислений (деление/умножение на степени 2); +
Формула устраняет нелинейность датчика.

[source,c++]
.Пример для STM32 чтения температуры
----
float read_bme280_temp() {
    uint8_t data[3];
    HAL_I2C_Mem_Read(&hi2c2, 0x76 << 1, 0xFA, I2C_MEMADD_SIZE_8BIT, data, 3, 100);
    int32_t adc_T = (data[0] << 12) | (data[1] << 4) | (data[2] >> 4);

    // Коэффициенты (заранее прочитаны при инициализации)
    int32_t var1 = (((adc_T >> 3) - (dig_T1 << 1)) * dig_T2) >> 11;
    int32_t var2 = ((((adc_T >> 4) - dig_T1) * ((adc_T >> 4) - dig_T1)) >> 12) * dig_T3) >> 14;
    int32_t t_fine = var1 + var2;

    return (t_fine * 5 + 128) >> 8;  // Температура в °C
}
----

Датчик калибруется на заводе — коэффициенты компенсируют погрешности. Формула обеспечивает точность ±1.0°C в диапазоне -40°C…+85°C. Целочисленные вычисления быстрее операций с плавающей точкой на MCU.

[NOTE]
====
Все калибровочные коэффициенты должны быть прочитаны при инициализации датчика (адреса 0x88…0x9F). Иначе температура будет неверной!
====

Считаем давление с датчика BME280.

. Чтение калибровочных коэффициентов (один раз при инициализации):
+
[source,cpp]
----
uint8_t calib_data[18];

// P1-P9 хранятся в calib_data[0..17]
----

. Чтение сырых данных давления:
+
[source,cpp]

HAL_I2C_Mem_Read(&hi2c2, BME280_ADDR, 0xF7, I2C_MEMADD_SIZE_8BIT, press_data, 3, 100);
uint32_t adc_P = ((press_data[0] << 12) | (press_data[1] << 4) | (press_data[2] >> 4));
----

. Применение калибровки (формула из даташита):
+
[source,cpp]
----
var1 = (t_fine >> 1) - 64000
var2 = (((var1 >> 2) * (var1 >> 2)) >> 11) * P6
var2 = var2 + ((var1 * P5) << 1)
var2 = (var2 >> 2) + (P4 << 16)
var1 = (((P3 * (((var1 >> 2) * (var1 >> 2)) >> 13)) >> 3) + ((P2 * var1) >> 1)) >> 18
var1 = ((32768 + var1) * P1) >> 15
pressure = 1048576 - adc_P
pressure = (pressure - (var2 >> 12)) * 3125
if (pressure < 0x80000000) {
  pressure = (pressure << 1) / var1
} else {
  pressure = (pressure / var1) * 2
}
var1 = (P9 * (((pressure >> 3) * (pressure >> 3)) >> 13)) >> 12
var2 = ((pressure >> 2) * P8) >> 13
pressure = pressure + ((var1 + var2 + P7) >> 4)
----

Для перевода давления в высоту (альтитуду) можно использовать барометрическую формулу.

[latexmath]
.Формула для расчета высоты над уровнем моря (в метрах)
++++
h = \frac{T_0}{L_0} \times \left[ \left( \frac{P}{P_0} \right)^{-\frac{R \times L_0}{g \times M}} - 1 \right]
++++
где \( P\) – текущее давление (Па); +
\( P_0\) – давление на уровне моря (стандартное = 101325 Па); +
\( T_0\) – стандартная температура на уровне моря (288.15 К); +
\( L_0\) – температурный градиент (0.0065 К/м); +
\( R\) – универсальная газовая постоянная (8.3144598 Дж/(моль·К)); +
\( g\) – ускорение свободного падения (9.80665 м/с²); +
\( M\) – молярная масса сухого воздуха (0.0289644 кг/моль); +

Для STM32 лучше использовать упрощенную формулу (менее ресурсоемкую).

[source,c++]
.Упрощенная формула
----
float pressureToAltitude(float pressure_Pa, float seaLevelPressure = 101325.0f) {
    return 44330.0f * (1.0f - powf(pressure_Pa / seaLevelPressure, 0.1903f));
}
----

Упрощенная формула дает погрешность ~0.3% в тропосфере. Для наших задач подобная погрешность является избыточной. Однако для научных задач следует использовать полную формулу.

Для оптимизации для платы STM32 рекомендуется не использовать powf() из ARM CMSIS-DSP и заменить функцию на линейную аппроксимацию для экономии ресурсов. powf() — это стандартная математическая функция в языке C, которая вычисляет степень числа с плавающей запятой. 

[NOTE]
====
Функция powf() требует значительных вычислительных ресурсов на микроконтроллерах (особенно без FPU), что может замедлить работу системы.
====

Линейная аппроксимация. В формуле для высоты используется powf(P/P0, 0.1903). Заменим её на линейную аппроксимацию в диапазоне давлений 700–1100 гПа (примерно до 3076 м). Тогда оптимизированная функция высоты будет:

[source,c++]
.Оптимизированная функция высоты
----
float approxPow(float x) {  // x = P/P0

==== Измерение влажности

[cols="1,3,2", options="header"]
.Регистры BME280 для работы с влажностью
|===
| Адрес (HEX) | Назначение | Размер (байт)
| `0xA1`      | Калибровочный коэффициент H1 (uint8) | 1
| `0xE1-0xE7` | Калибровочные коэффициенты H2-H6 (int16/int8) | 7
| `0xFD`      | MSB влажности (биты 15-8) | 1
| `0xFE`      | LSB влажности (биты 7-0) | 1
| `0xF2`      | Контрольный регистр влажности (ctrl_hum) | 1
|===

Алгоритм работы:

. _Настройка режима:_
+
[source,cpp]
----
// Установка oversampling x2 (биты 2:0 = 010)
uint8_t ctrl_hum = 0b010;
HAL_I2C_Mem_Write(&hi2c2, BME280_ADDR, 0xF2, I2C_MEMADD_SIZE_8BIT, &ctrl_hum, 1, 100);
----

. _Чтение калибровочных коэффициентов:_
+
[source,cpp]
----
uint8_t hum_calib[7];
HAL_I2C_Mem_Read(&hi2c2, BME280_ADDR, 0xE1, I2C_MEMADD_SIZE_8BIT, hum_calib, 7, 100);

// Разбор коэффициентов:
int16_t H2 = (hum_calib[1] << 8) | hum_calib[0]; // 0xE1-0xE2
int16_t H4 = (hum_calib[3] << 4) | (hum_calib[4] & 0x0F); // 0xE4-0xE5 (12 бит)
int16_t H5 = (hum_calib[5] << 4) | (hum_calib[4] >> 4);   // 0xE5-0xE6 (12 бит)
----

. _Чтение сырых данных:_
+
[source,cpp]
----
uint8_t hum_data[2];
HAL_I2C_Mem_Read(&hi2c2, BME280_ADDR, 0xFD, I2C_MEMADD_SIZE_8BIT, hum_data, 2, 100);
int32_t adc_H = (hum_data[0] << 8) | hum_data[1]; // 16-битное значение
----

. _Расчёт относительной влажности (формула из даташита):_
+
[latexmath]
++++
var_H = (t_fine - 76800)
humidity = (adc_H - (H4 \times 64 + H5 \times var_H / 16384)) \times H2 / 65536 \times (1 + H6 / 67108864 \times var_H \times (1 + H3 / 67108864 \times var_H))
++++
+
где \( t_fine\) – вычисляется при измерении температуры. +

Пример кода для платы STM32:

[source,cpp]
----
float readBME280Humidity() {
    // 1. Чтение калибровочных коэффициентов (один раз при инициализации)
    static int32_t t_fine = ...; // Получается из температуры
    
    // 2. Чтение сырых данных
    uint8_t data[2];
    HAL_I2C_Mem_Read(&hi2c2, BME280_ADDR, 0xFD, 1, data, 2, 100);
    int32_t adc_H = (data[0] << 8) | data[1];
    
    // 3. Расчёт по формуле
    int32_t var_H = (t_fine - 76800);
    var_H = ((((adc_H << 14) - (H4 << 20) - (H5 * var_H)) + 16384) >> 15) * 
            (((((((var_H * H6) >> 10) * (((var_H * H3) >> 11) + 32768)) >> 10) + 2097152) * H2 + 8192) >> 14);
    var_H = var_H - ((((var_H >> 15) * (var_H >> 15)) >> 7) * H1 >> 4);
    
    // Ограничение 0-100%
    return (var_H < 0) ? 0 : (var_H > 100000) ? 100.0f : (float)var_H / 1024.0f;
}
----

==== Датчик DS18B20

DS18B20 – высокоточный цифровой датчик температуры. 

**Основные характеристики:**

*   Диапазон: -55.. 125 °C
*   Точность: 0.5 °C
*   Разрешение: 9.. 12 бит (0.48.. 0.06 °C)
*   Питание: 3-5.5V (совместим с STM32 3.3V)
*   Период выдачи результата:
*   750 мс при точности 12 бит
*   94 мс при точности 9 бит
*   Интерфейс связи: 1-Wire (OneWire)
*   Корпус: TO-92, SOIC-8 или герметичное исполнение

Алгоритм чтения температуры:

. Инициализация шины 1-Wire (Reset Pulse)
. Отправка команды `0xCC` (Skip ROM) - если датчик один на линии
. Отправка команды `0x44` (Start Conversion)
. Ожидание завершения преобразования (750 мс для 12-бит)
. Reset + Skip ROM (`0xCC`) + команда `0xBE` (Read Scratchpad)
. Чтение 9 байт (первые 2 байта - температура)
. Конвертация в градусы

[cols="1,3,2", options="header"]
.Регистры DS18B20
|===
| Адрес | Назначение          | Размер 
| 0x00-0x01 | Температура (LSB, MSB) | 2 байта
| 0x02-0x04 | TH, TL, Configuration | 3 байта
| 0x08      | CRC                  | 1 байт
|===


[source,c++]
.Код для STM32 (HAL)
----
// Настройка GPIO (PA0 как выход с открытым стоком)
#define DS18B20_PIN  GPIO_PIN_0
#define DS18B20_PORT GPIOA

// Функция чтения температуры
float readDS18B20() {
    uint8_t data[9];
    
    // 1. Инициализация
    HAL_GPIO_WritePin(DS18B20_PORT, DS18B20_PIN, 0);
    HAL_Delay(480); // Reset pulse
    HAL_GPIO_WritePin(DS18B20_PORT, DS18B20_PIN, 1);
    HAL_Delay(60);  // Ожидание Presence pulse
    
    // 2. Запуск преобразования
    write1Wire(0xCC); // Skip ROM
    write1Wire(0x44); // Convert T
    HAL_Delay(750);   // Ожидание для 12-бит
    
    // 3. Чтение данных
    reset1Wire();
    write1Wire(0xCC); // Skip ROM
    write1Wire(0xBE); // Read Scratchpad
    for (int i = 0; i < 9; i++) data[i] = read1Wire();
    
    // 4. Конвертация
    int16_t temp_raw = (data[1] << 8) | data[0];
    return (float)temp_raw / 16.0f; // 12-битный режим
}
----

[source,c++]
.Оптимизация для FreeRTOS
----

    while (1) {
        float temp = readDS18B20();
        vTaskDelay(pdMS_TO_TICKS(1000)); // Опрос каждую секунду
    }
}

=== Период измерения с использованием FreeRTOS

Для точного соблюдения временных интервалов в FreeRTOS лучше всего использовать vTaskDelayUntil(), который исключает накопление погрешности от времени выполнения кода.

[source,c++]
.
----
#include "FreeRTOS.h"
#include "task.h"

void vSensorTask(void *pvParameters) {
    TickType_t xLastWakeTime;
    const TickType_t xFrequency = pdMS_TO_TICKS(500); // 500 мс в тиках
    
    // Запоминаем текущее время при старте
    xLastWakeTime = xTaskGetTickCount();

    while (1) {
        // Выполняем измерения
        float temp = readDS18B20();
        float humidity = readBME280Humidity();
        
        // Применяем цифровой фильтр
        // ...
        
        // Точная задержка до следующего цикла
        vTaskDelayUntil(&xLastWakeTime, xFrequency);
    }
}
----

Разница между vTaskDelay() и vTaskDelayUntil():

vTaskDelay(500)	имеет накопление погрешности, что требует дополнительной задержки от текущего момента. vTaskDelayUntil()	имеет фиксированный интервал между концами циклов, за счет чего гарантирует 500 мс между запусками. 

При использования FreeRTOS важна настройка таймера в FreeRTOSConfig.h.

[source,cpp]
.Настройка таймера
----
#define configTICK_RATE_HZ 500  // 1 тик = 1 мс (для pdMS_TO_TICKS(500))
----

=== Цифровая фильтрация

[latexmath]
++++
\tau = \int\binom{1-e^\frac{-dt}{RC}, RC > 0 sec}{1,RC \leq 0 sec}
++++
[latexmath]
++++
FilteredValue = OldFiltered + (Value - OldValue) * \tau
++++

[source,cpp]
.Реализация цифрового фильтра
----
void setTau(float dt, float rc) {
        tau = (rc <= 0) ? 1.0f : (1.0f - expf(-dt / rc));
    }
    float filter(float new_value) {
        old_value += (new_value - old_value) * tau;
        return old_value;
    }

=== USART-настройки

USART (Universal Synchronous/Asynchronous Receiver/Transmitter) — это аппаратный модуль в микроконтроллерах для последовательной передачи данных.
Поддерживает два режима:

* Асинхронный (UART) — без общего тактового сигнала;
* Синхронный — с тактовым сигналом (как SPI).

[cols="1,3,2", options="header"]
.Ключевые регистры USART (для STM32F4xx)
|===
| Регистр         | Назначение                          | Биты (важные)
| USART_CR1       | Управление 1                        | UE, TE, RE, M, PCE, PS
| USART_CR2       | Управление 2                        | STOP[1:0] (стоп-биты)
| USART_CR3       | Управление 3                        | DMAT (DMA для передачи)
| USART_BRR       | Baud Rate Register                  | DIV_Mantissa, DIV_Fraction
| USART_DR        | Data Register (приём/передача)      | 9 бит данных
| USART_ISR       | Status Register                     | TXE, TC, RXNE, ORE
| USART_GTPR      | Guard Time (только для SmartCard)   | -
|===


Рассмотрим дитально регистры.

USART_CR1 это главный регистр управления USART. Определяет основные параметры работы.

[cols="1,2", options="header"]
.USART_CR1 (Control Register 1)
|===
| Бит | Описание
| 13 UE       | Включение USART (1 - включён)
| 12 M        | Длина слова (0 - 8 бит, 1 - 9 бит)
| 10 PCE      | Контроль чётности (1 - включён)
| 9 PS        | Выбор чётности (0 - чётная, 1 - нечётная)
| 8 PEIE      | Прерывание по ошибке чётности
| 3 TE        | Включение передачи (1 - включён)
| 2 RE        | Включение приёма (1 - включён)
|===


USART_BRR задаёт скорость обмена (бодрейт). Рассчитывается по формуле:
[latexmath]
++++
BRR = \frac{f_{CK}}{16 \times BaudRate}
++++
где \({f_{CK}}\) – тактовая частота USART (обычно 84 МHz на STM32F4).; +


[source,cpp]
.Настройка USART через HAL
----
// 1. Инициализация структуры

=== Настройка DMA для USART

[source,cpp]
.Ключевые биты для DMA
----
typedef struct {
  uint32_t DMAT    :1;  // Bit 7: DMA для передачи (1=вкл)
  uint32_t DMAR    :1;  // Bit 6: DMA для приёма (1=вкл)
  uint32_t HDSEL   :1;  // Bit 3: Полудуплексный режим
  uint32_t EIE     :1;  // Bit 0: Прерывание по ошибке
} USART_CR3_Bits;
----

Пример включения DMA для передачи: USART1->CR3 |= USART_CR3_DMAT;  // Включить DMA для TX

Конфигурация DMA:

. Включите DMA для USART2:
** TX Mode: Memory to Peripheral
**  RX Mode: Peripheral to Memory
. Настройте приоритет: Medium
. Режим: Normal (не Circular для однократной передачи)
